## 2. 用户本轮指出的 5 个问题：根因（已核对代码）

### 2.1 黑框 / 抠图脏（截图 1 GPT、截图 3 Claude）

不是单一原因，是 5 层叠加：

1. **参考图自带黑描边，被降采样保留**。`tools/make_pixel_sprites.py` 先把 Q 版插图降到 64px，插图的黑色轮廓线仍在，变成 1–2px 脏边。
2. **再叠加 2px 烘焙描边**。`make_pixel_sprites.py` 的 `add_outline(..., size=2)` 又加 2px；角色描边色是近黑（DeepSeek `(20,26,64)`、GPT `(20,19,38)`、Claude `(62,32,18)`）。
3. **运行时再叠 1px 着色器描边**。`player.gd` 给 `AnimatedSprite2D` 挂了 `shaders/sprite_outline.gdshader`，`outline_size=1.0`。总描边 = 2 + 1 = **3px**，在 64px 角色上占身体宽度约 10%，放大后就是“黑框”。
4. **提亮把边缘对比拉爆**。`player.gd` 里 `anim.self_modulate = Color(1.32,1.32,1.38)`，内部变亮、黑边不变，边缘更黑更厚。
5. **程序化配饰是平滑多边形**。`scripts/player/char_accent.gd` 用 `draw_colored_polygon` + **1.2px 抗锯齿 `draw_polyline`** 画 GPT 龙翼、DeepSeek 鲸尾、Claude 向日葵。它们贴在角色背后，边缘深、形状不规则，在第一眼就是“意义不明的黑块”。这既不是像素，也不跟帧对齐。

另外：
- `assets/sprites/gpt/idle.png.import` 里 `process/fix_alpha_border=true`；配合半透明边缘会把颜色渗到透明像素，缩小后形成脏点。
- 64px 帧在 2× 窗口上 = 128px 屏幕像素，3px 描边 = **6px 屏幕黑边**，用户截图是局部放大，所以看起来像“屎”。
- 所有 UI 根节点都用了 `TEXTURE_FILTER_LINEAR`（`main_menu.gd`、`character_select.gd` 等），角色选择/立绘是糊的；这与像素方向冲突。

**结论**：不是“抠图算法差”，是“来源黑边 + 2px 烘焙 + 1px 着色器 + 提亮 + 平滑配饰”五连击。P0 先拆掉后四层，P1 重画并只保留 1px 单色描边。

### 2.2 GPT 设计“垃圾”

- 当前是“白毛 + 白裙 + 浅紫细节”直接降采样，白对白没有层次；龙角、龙翼、龙尾在 64px 被压没，只剩下一个白色团块。
- 2px 近黑描边把白发轮廓糊成一圈黑，脸只有 1–2 个像素的眼睛，读不出“龙娘”。
- `char_accent.gd` 的龙翼是灰紫多边形 + 深边，和白色身体叠在一起，更像背后一块黑框，而不是翅膀。
- 参考图 `gpt_chibi_3view_hd.png` 的签名特征是：白色长发、淡紫龙角、紫色眼睛、背后小龙翼、粗龙尾、白裙淡紫滚边。**像素版必须保留这 5 个特征中的至少 4 个**，否则就不是 GPT。

### 2.3 “靶”字到底有什么用

- `training_room.gd` 在中心画了一个 26px 深色圆，并在上面写「靶」。它是**弹幕发生器**的位置标记，不是可被打的靶子，也不参与伤害。
- 真正的 `TrainingTarget` 只在 `tutorial_guide.gd` 第 1 步生成一个；第 3 步生成一个射手。教程完成后不再生成。
- 所以用户看到的「靶」= 一个不会掉血、没有反馈、挡住视野的装饰字。**没有游戏作用**。P0 删掉它，改成有机器造型的「弹幕发生器」，并另放 3 个真靶子。

### 2.4 训练场空、怪物看不见

- `training_room.gd::_ready()` 清空 `GameState.enemies`、`crates`、`obstacles`，只加房间、玩家、UI、发生器。
- 教程完成后，`tutorial_guide.gd` 不再生成靶子/敌人；`_process` 只循环弹幕。
- 所以场景里只有地板、玩家、弹幕、一个「靶」字。不是怪物隐身，是**根本没有怪物**。
- 另外若后续加敌人，必须进 `enemy_layer` 并保证 `z_index ≥ 2`；训练场根节点没有 y-sort，直接 `add_child` 容易与地板/UI 层级打架。P0/P5 一起修。

### 2.5 ESC 菜单与退出训练场冲突

- `main.gd::_unhandled_input()`：当前场景 `is_gameplay` 时，ESC 打开暂停菜单。
- `training_room.gd::_unhandled_input()`：ESC 直接 `_exit()`，**没有 `get_viewport().set_input_as_handled()`**。
- 同一帧两个 handler 都收到 ESC：暂停菜单开了，训练场也退了；`main._swap()` 只 `queue_free()` 训练场，**没有关暂停菜单**；`show_select()` 也不关。于是“退出训练场后 ESC 菜单还在”。
- 修复原则：**ESC 只能有一个主人**。统一由 `main.gd` 管暂停；训练场不再监听 ESC；暂停菜单里加「退出训练场」按钮；`_swap()` 无条件 `_close_pause()`。手柄 Start/Back 同理。

## 3. 总美术方向：Soul Knight × Enter the Gungeon

### 3.1 借什么、不借什么

| 来源 | 借 | 不借 |
|---|---|---|
| 元气骑士 | 2.5 头身、1px 深色外描边、饱和三阶明暗、大眼、武器前握、轮廓一眼可读、角色小动作 | 具体角色/武器造型、Q 版圆润到没有棱角 |
| 挺进地牢 | 地牢的暗色空间、弹幕可读性、房间节奏、枪械种类与剪影、Boss 血条分段、信息密度 | 4 方向全套动画（本轮不做）、过度噪点、像素级抖动到看不清 |
| 现有 AI 主题 | 终端/服务器/数据中心的冷色调、角色 AI 梗、Token/配额叙事 | 蓝白渐变玻璃、圆角卡片、柔和阴影、5px 小字 |

### 3.2 全局像素规约（12 条，违反即打回）

1. 所有美术按 **1× 像素网格**设计；禁止在 1× 上做抗锯齿。
2. 外轮廓 **只允许 1px**；颜色用该角色/物体的深色版本，不用纯黑。
3. 每个材质最多 3 阶（暗/中/亮）+ 1px 高光；全角色调色板 ≤ 20 色。
4. 透明像素 alpha 只能是 0 或 255；不允许 0<alpha<255（阴影单独一层）。
5. 光源统一左上；右下 1px 暗边，左上 1px 亮边。
6. 禁止渐变；需要过渡用 2×2 棋盘/4×4 Bayer 抖动。
7. 禁止圆角、软阴影、发光圆斑；阴影用硬边椭圆/矩形，透明度 ≤ 35%。
8. 位置、尺寸、相机全部整数；相机 `snap_2d_transforms_to_pixel`。
9. 纹理过滤 NEAREST；mipmap 关闭；像素图不做三分/ VRAM 压缩。
10. UI 最小字号 12px；字号只用 12/24/36；不缩放像素字体到非整数倍。
11. 角色/敌人/子弹必须在任何地板色上可读：深色地板给亮边，浅色地板给深边。
12. 不复制参考游戏素材；只做气质与结构借鉴。

## 5. P1：像素美术地基 + 角色重绘

### 5.1 重写精灵管线：不要“降采样 + 描边”，改成“像素木偶编译器”

现状 `make_pixel_sprites.py` 是“把插图缩小 → 量化 → 加描边”，这是黑框/脏边的源头。P1 改成数据驱动的**像素木偶**：

```
tools/pixel_puppet.py           # 新管线：调色板 + 部件几何 + 帧变换
tools/palettes/{id}.gpl         # 每角色调色板（可选 Aseprite 可直接用）
tools/validate_sprites.py       # 自动验收
```

管线规则：
- 每角色定义 `PALETTE`（≤20 色）、`PART`（头/发/角/翼/尾/裙/腿/臂/道具）、`FRAME`（idle 4、walk 6、attack 4、roll 4）。
- 所有部件用整数矩形/像素椭圆/像素多边形拼；不允许从插图直接缩放。
- 先画“剪影掩码”，再填 3 阶色，再沿剪影外边界加 **1px 深色描边**；内部结构线不用黑，用暗阶。
- 眼睛 2–3px，带 1px 高光；嘴 1–2px；腮红 2×1；脸不画鼻子。
- 头顶/脚底/左右留 2–4px 安全边；所有帧锚点一致，脚底 y=60。
- idle：整体 1px 上下；walk：腿 1px 交替、头发/尾巴 1px 摆；attack：手臂/道具 2px 前伸；roll：压成 44×44 球，保留 2 个特征色块。
- 输出横排帧表：`assets/sprites/{id}/{idle,walk,attack,roll}.png`，每帧 64×64。
- 另出 `assets/sprites/{id}/icon_32.png`（头像 32×32）供 HUD。

**参考图只用于“采样颜色 + 确认轮廓特征”，不做逐像素缩小。** 高清三视图下采样只能用于生成 96×128 立绘，不能用于 64px 战斗帧。

### 5.2 自动验收 `validate_sprites.py`

必须检查并返回非 0：
- 宽能被 64 整除，高 64。
- alpha 只有 0/255；轮廓外 1px 内不得出现半透明。
- 剪影 bbox 在 `x∈[2,62]`、`y∈[4,62]`，不贴边。
- 描边厚度 ≤1px（对剪影做 1 次膨胀，差集即描边；检查差集宽度）。
- 每帧调色板 ≤20；帧间脚底锚点漂移 ≤1px；同动画相邻帧剪影面积差 ≤12%。
- 输出 `tests/_sprite_sheet_{id}.png`：1×/2×/4×，四种背景（白 `#FFFFFF`、中灰 `#7A8AA8`、深蓝 `#101018`、棋盘）。
- 人眼验收：1× 下能一眼认出角色；4× 下外圈不超过 1px 深色。

### 5.3 渲染与导入设置

`project.godot`：
```ini
[rendering]
textures/canvas_textures/default_texture_filter=0
2d/snap/snap_2d_transforms_to_pixel=true
2d/snap/snap_2d_vertices_to_pixel=true
anti_aliasing/quality/msaa_2d=0
```
- 所有 `AnimatedSprite2D` / `Sprite2D` / UI 像素贴图显式 `texture_filter = TEXTURE_FILTER_NEAREST`。
- 删除 `shaders/sprite_outline.gdshader` 的使用；文件可保留但不再挂到玩家。Boss 若需要描边，用烘焙描边，不用 shader。
- 相机：`position_smoothing_enabled=false`，或每帧 `camera.global_position = camera.global_position.round()`；禁止亚像素滚动。
- 角色脚底加 1 个 12×3 硬边椭圆阴影（黑 30%），不要软阴影。

## 7. P3：角色武器重设计

### 7.1 现状问题（已核对代码）

- 所有手持武器统一 `draw_size=20`，但源图是 32×32 → **非整数缩小**，像素必糊。
- GPT 专武 `excl_codex.gd` 直接复用 `gpt_starter.png`，专武和初始武器长得一样。
- DeepSeek 专武 Harness、Claude 专武锤子是 `hand_device.gd` 里用 `draw_rect` 画的**程序化方块/海豚**（`proc="orca"` / `"hammer"`），不是像素美术。
- 武器没有 24×24 图标，角色选择/HUD 只能写文字。
- 武器造型与角色身份弱关联：饭盆/云杖/法典有概念，但像素剪影不成立。

### 7.2 设计原则

- 每把武器先定 **1 个 24px 可读剪影**：饭盆=开口碗+斜插 Token；龙杖=弯钩+云球；法典=打开的书+书签；海妖=虎鲸头+鱼叉；法槌=T 形槌+葵花；铁盆=凹盆+提手。
- 3 阶色 + 1px 深描边 + 1px 高光；金属加 1px 冷高光，木头加 1px 暖高光。
- 手持图 32×32，**按 32 整数绘制**；不再缩到 20。`hand_device.gd` 改为每把武器可配 `draw_size`（32 或 24）与 `grip_offset`。
- 每把武器 3 帧：待机/开火/后坐；枪口 2 帧像素星；弹丸 8×8 2 帧。
- 图标 24×24 与手持图同色同形，UI 一眼对应。

## 13. 风险与避坑

| 风险 | 说明 | 对策 |
|---|---|---|
| AI 出像素图不可控 | 直接让图像模型出 64px 帧表，帧不对齐、描边脏 | 用代码像素木偶；参考图只采色/定轮廓 |
| 字体体积 | CJK 像素字体 3–6MB，Web 首屏变慢 | 只打包 12px 一个字重；子集化；加载前用占位 |
| 像素字体非整数缩放 | 12px 字体拉到 16/20 会糊 | 字号只 12/24/36；布局按 12 网格 |
| UI 小数坐标 | Container 分数宽高导致 1px 边糊 | 所有面板宽高取整到 2/4；截图检查 |
| 相机亚像素 | smoothing 导致像素抖动/糊 | 关 smoothing 或每帧 round；`snap_2d_*` |
| ESC 再冲突 | 新 UI 又加自己的 ESC | 输入路由表：ESC 只归 main；子界面用 `ui_cancel` 消费 |
| Web 性能 | 小肥鱼/粒子/光照过多 | 池化；软上限 8；低画质降抖动/光照 |
| 存档兼容 | 新增 quota 字段旧档缺 | `RunSave` 默认值 + 迁移版本号 |
| 版权 | 大肥鱼是 B 站同人角色 | 非官方同人标注；不商用；素材自绘 |
| 参考游戏素材 | 直接抄元气/地牢 | 只借比例与结构；所有贴图自绘 |
| 版本幻觉 | GLM 包写 4.4.1 / bullet 无 friendly | 以本文 §1 为准 |
